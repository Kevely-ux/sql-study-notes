Exercício 1 — modelos do e-commerce Turma A e B: 16/08

  1. A partir do texto crie o modelo conceitual, o modelo lógico e o modelo lógico normalizado.
  2. Texto: cada cliente (nome, e-mail, senha, endereço de entrega) pode fazer compras de vários produtos. Cada produto pertence a uma categoria (nome e descrição) e tem nome, preço e descrição.
  3. Entregar os diagramas em PDF ou JPG.
Como resolver (dicas, sem a resposta pronta)

Tente primeiro no MySQL Workbench. Cada dica diz onde procurar e o que conferir; o código mesmo você escreve e testa.

  1. Substantivos = entidades. Sublinhe no texto: cliente, produto, categoria e compra. Tudo que só descreve alguém (nome, e-mail, preço) vira atributo.
  2. Verbos = relacionamentos. Leia "cliente faz compras de produtos" e pergunte dos dois lados: um cliente faz quantas compras? uma compra tem quantos produtos? um produto aparece em quantas compras?
  3. Categoria é 1:N com produto (um produto pertence a uma categoria; uma categoria tem vários produtos).
  4. Lógico: toda relação 1:N gera uma FK do lado N; uma relação N:N gera uma tabela nova com as duas chaves. Descubra qual das relações acima é N:N.
  5. Normalizado: confira se o endereço de entrega e o preço aparecem repetidos onde não deveriam. Pergunte: o preço do produto hoje muda o valor de compras antigas?
  6. Teste: para cada linha do diagrama consiga apontar a coluna FK que a representa.

02

UNION, INTERSECT, EXCEPT, CASE, HAVING e WITH

10/08 - 11/08/2026

Como combinar consultas, criar colunas calculadas com condição, filtrar grupos e reaproveitar o resultado de uma busca.

Query

  • Cada comando SQL é individual: SELECT busca em 1 ou + tabelas e exibe, INSERT, UPDATE e DELETE mexem em 1 tabela e acabam ali.
  • Para combinar comandos existem UNION, INTERSECT e EXCEPT.

UNION, INTERSECT, EXCEPT

  • Forma geral: <SELECT> UNION ou INTERSECT ou EXCEPT <SELECT>. Os dois SELECT têm o mesmo número de colunas.
  • UNION: junta tudo e ignora repetidos (usado para simular o FULL JOIN). UNION ALL: junta tudo, com repetidos.
  • INTERSECT: valores comuns aos dois. EXCEPT: o que está no 1º e não está no 2º.
Slides: tabelas numero (1 a 10) e numero_par (2 a 10)
SELECT valor FROM numero
UNION
SELECT valor FROM numero_par;      -- 1..10 sem repetir

SELECT valor FROM numero
UNION ALL
SELECT valor FROM numero_par;      -- 15 linhas (2,4,6,8,10 repetem)

SELECT valor FROM numero
INTERSECT
SELECT valor FROM numero_par;      -- 2,4,6,8,10

SELECT valor FROM numero
EXCEPT
SELECT valor FROM numero_par;      -- 1,3,5,7,9

CASE

  • Funciona como o if/else ou switch de programação: CASE WHEN <condição> THEN <resultado> ... ELSE <resultado> END.
  • Dê nome à coluna com END AS 'nome'. O WHEN é avaliado de cima para baixo e vale o primeiro que for verdadeiro.
  • Dá para aninhar: ELSE CASE WHEN ... END.
SELECT valor,
  CASE
    WHEN valor % 5 = 0 THEN 'Múltiplo de 5'
    WHEN valor % 3 = 0 THEN 'Múltiplo de 3'
    WHEN valor % 2 = 0 THEN 'Par'
    ELSE 'Ímpar'
  END AS 'Análise'
FROM numero;

-- aninhado: primeiro par/ímpar, depois só o ímpar é analisado
SELECT valor,
  CASE
    WHEN valor % 2 = 0 THEN 'Par'
    ELSE CASE
      WHEN valor % 5 = 0 THEN 'Múltiplo de 5'
      WHEN valor % 3 = 0 THEN 'Múltiplo de 3'
      ELSE 'Ímpar'
    END
  END AS 'Análise'
FROM numero;

GROUP BY, HAVING e ORDER BY

  • GROUP BY agrupa o resultado e precisa de uma função de agregação: COUNT, SUM, AVG, MAX, MIN.
  • ORDER BY qtd DESC ordena pelo apelido, do maior para o menor.
  • Filtrar o resultado do grupo com WHERE não funciona: com o apelido dá erro 1054 (Unknown column) e com a função direta dá erro 1111 (Invalid use of group function).
  • HAVING é o WHERE dos agrupamentos. Pode existir WHERE e HAVING na mesma consulta.
Tabela exercicio (numero, id_aluno, nota)
SELECT numero, COUNT(numero) AS qtd, AVG(nota) AS media
FROM exercicio
GROUP BY numero
HAVING media > 6
ORDER BY qtd DESC;

WITH (CTE)

  • O resultado de uma busca é usado por outro comando. Funciona como uma tabela temporária com nome: WITH nome(colunas) AS (SELECT ...).
  • Serve para o SELECT, mas também para INSERT, UPDATE e DELETE.
WITH info_temp(numero, quantidade, media) AS (
  SELECT numero, COUNT(numero), AVG(nota) FROM exercicio GROUP BY numero)
SELECT numero, quantidade, media
FROM info_temp
WHERE media > 6
ORDER BY quantidade DESC;

-- WITH dentro do INSERT
INSERT INTO calculado(exercicio, quantidade, media)
WITH info_temp(numero, quantidade, media) AS (
  SELECT numero, COUNT(numero), AVG(nota) FROM exercicio GROUP BY numero)
SELECT numero, quantidade, media FROM info_temp WHERE media > 6;

-- WITH antes do UPDATE (com JOIN) e do DELETE
WITH info_temp(numero, quantidade, media) AS (
  SELECT numero, COUNT(numero), AVG(nota) FROM exercicio GROUP BY numero)
UPDATE calculado
INNER JOIN info_temp ON info_temp.numero = calculado.exercicio
SET calculado.quantidade = info_temp.quantidade, calculado.media = info_temp.media;

03

Subquery e índice

17/08 - 18/08/2026

Uma consulta dentro de outra, em todos os comandos, e como acelerar buscas com índices.

  • Subquery é uma query dentro de outra query: um SELECT dentro de outro comando.
  • Tabelas dos slides: numero_par, numero_impar e numero_texto (valor, texto em português, texto_ingles).

Subquery no SELECT (5 lugares)

#Onde entraExemplo do slide
1Como coluna do selectSELECT valor, (SELECT texto FROM numero_texto WHERE valor = numero_par.valor) AS 'Texto Português' FROM numero_par
2Como filtro no WHEREWHERE valor IN (SELECT valor FROM numero_par)
3Como uma tabela (exige apelido)FROM (SELECT valor FROM numero_impar ORDER BY valor) AS tabela
4Como filtro no HAVINGGROUP BY valor HAVING valor IN (SELECT valor FROM numero_impar)
5Como campo de ordenaçãoORDER BY (SELECT texto FROM numero_texto WHERE valor = numero_par.valor)
  • Se a subquery usada como coluna devolver 2 colunas (texto, texto_ingles) dá erro 1241 (Operand should contain 1 column).

Subquery no INSERT, UPDATE e DELETE

-- INSERT: como fonte dos dados
INSERT INTO numero_par_texto(valor, texto, texto_ingles)
SELECT valor, texto, texto_ingles FROM numero_texto WHERE valor % 2 = 0;

-- INSERT: como parte da informação
INSERT INTO numero_par_texto(valor, texto, texto_ingles)
VALUES ((SELECT (COUNT(valor)+1)*2 FROM numero_par), '', '');

-- UPDATE: como nova informação
UPDATE numero_par_texto
SET texto = (SELECT texto_ingles FROM numero_texto WHERE valor = numero_par_texto.valor);

-- UPDATE e DELETE: como filtro no WHERE
UPDATE numero_par_texto SET texto_ingles = 'Texto em inglês'
WHERE valor IN (SELECT valor FROM numero_texto);

DELETE FROM numero_par_texto
WHERE valor IN (SELECT valor FROM numero_texto);
!

O que não pode: no INSERT, UPDATE e DELETE a subquery não pode usar a mesma tabela que está sendo alterada.

Índice e EXPLAIN ANALYZE

  • Índice é como o índice de um livro: acha o assunto sem folhear página por página. Serve para otimizar buscas.
  • Use nas colunas mais usadas em busca. Cuidado: índice em tudo deixa inserir, atualizar e deletar mais custoso.
  • EXPLAIN ANALYZE explica como o comando roda e quanto tempo levou, para ver (ou não) o ganho do índice.
  • Sem índice aparece Table scan; com índice, Covering index scan ou range scan.
  • Com 100 linhas o ganho é mínimo (0,0054 ms). Com 121.643 linhas, WHERE valor > 100 AND valor < 1000 o índice economizou cerca de 28 ms no total: o banco leu só as 449 linhas do intervalo em vez de varrer todas.
CREATE INDEX index_numero_par ON numero_par(valor);
DROP INDEX index_numero_par ON numero_par;

EXPLAIN ANALYZE SELECT valor FROM numero_par WHERE valor > 100 AND valor < 1000;

04

View

24/08 - 25/08/2026

Uma "tabela" virtual definida por um SELECT, útil para esconder colunas e guardar consultas frequentes.

  • View significa visão: um jeito de olhar as informações. Parece uma tabela, mas não guarda os dados (não copia nada da tabela original).
  • Para que serve: (1) dar acesso só a algumas colunas (permissão é por tabela, não por coluna) e (2) guardar uma consulta complicada e frequente, como um relatório.
  • Se entra um novo aluno na tabela original, ele aparece na view se estiver no resultado da consulta que monta a view.
  • A view pode ter INNER JOIN, LEFT JOIN, RIGHT JOIN, UNION, INTERSECT e EXCEPT: o SELECT é quem decide.
CREATE VIEW view_aluno AS
SELECT nome, ra
FROM aluno
ORDER BY nome;

DESC view_aluno;
SELECT * FROM view_aluno;
DROP VIEW view_aluno;

A view aceita UPDATE, INSERT e DELETE?

  • Depende da permissão. Numa view de uma tabela só e SELECT simples, sim, e mexe na tabela original.
  • UPDATE view_aluno SET ra = '999' WHERE nome = 'Danilo' mudou o RA na tabela aluno.
  • INSERT na view funciona, mas avisa 1423 (Field of view ... doesn't have a default value) porque as outras colunas são NOT NULL. Dependendo da política pode bloquear.
  • DELETE na view também apaga da tabela original.
  • View com UNION (mais de uma fonte) é só leitura: UPDATE dá erro 1288 (target table ... is not updatable).

05

Trigger e function

31/08 - 01/09/2026

Ações automáticas disparadas por INSERT, UPDATE e DELETE, e funções próprias que devolvem um valor.

Trigger (gatilho)

  • Quando acontece um INSERT, UPDATE ou DELETE, o trigger executa uma ação automática. Pode ser antes ou depois de cada um dos três: 6 combinações.
  • NEW é a linha nova (existe no INSERT e no UPDATE); OLD é a linha antiga (existe no UPDATE e no DELETE).
  • Os comandos de dentro têm ;, que é o fim de uma query, então troque o delimitador: DELIMITER $$ ... END $$ ... DELIMITER ;.
  • SIGNAL SQLSTATE '45000' gera uma exceção definida pelo usuário e o MESSAGE_TEXT é a mensagem. Aparece como erro 1644.
  • SHOW TRIGGERS; lista os triggers e SHOW CREATE TRIGGER nome mostra um deles.
BEFORE INSERT: validar
DELIMITER $$
CREATE TRIGGER trigger_before_insert_salario
BEFORE INSERT ON salario
FOR EACH ROW
BEGIN
  IF NEW.remuneracao < 0 THEN
    SIGNAL SQLSTATE '45000'
    SET MESSAGE_TEXT = 'Remuneração deve ser positiva';
  END IF;
END $$
DELIMITER ;
AFTER INSERT: registrar em outra tabela (log)
DELIMITER $$
CREATE TRIGGER trigger_after_insert_salario
AFTER INSERT ON salario
FOR EACH ROW
BEGIN
  INSERT INTO log_salario(id_salario, nome_funcionario, remuneracao_anterior,
                          remuneracao_nova, datahora, usuario)
  VALUES (NEW.id, NEW.nome_funcionario, 0.0, NEW.remuneracao,
          CURRENT_TIMESTAMP(), USER());
END $$
DELIMITER ;
As outras combinações (resumo)
BEFORE UPDATE:  IF OLD.remuneracao > NEW.remuneracao THEN SIGNAL ... -- não pode diminuir
BEFORE DELETE:  IF OLD.remuneracao < (media/2) OR OLD.remuneracao = maximo THEN SIGNAL ...
AFTER DELETE:   <comandos>   -- só roda se o delete foi permitido
  • Problemas: um trigger que faz INSERT na mesma tabela que o disparou até pode ser criado, mas não executa: erro 1442.
  • Loop entre tabelas: insert na tabela 1 dispara trigger que escreve na 2, que dispara trigger que escreve na 1...
  • Trigger x FK: o DELETE do id 2 passou pelo trigger, mas quem barrou foi a chave estrangeira (erro 1451).

Function

  • Como AVG, COUNT, MAX, MIN, SUM, mas criada por você. Recebe parâmetros e devolve um valor com RETURN.
  • Forma: CREATE FUNCTION nome(parâmetros) RETURNS tipo <DETERMINISTIC> BEGIN ... RETURN ...; END$$.
  • Chama-se dentro de um SELECT, linha a linha. DROP FUNCTION nome apaga.
DELIMITER $$
CREATE FUNCTION verificar_salario_2000(salario DECIMAL(9,2))
RETURNS VARCHAR(100)
DETERMINISTIC
BEGIN
  DECLARE resultado VARCHAR(100);
  IF salario >= 2000 THEN SET resultado = 'Maior ou igual a 2000';
  ELSE SET resultado = 'Menor que 2000';
  END IF;
  RETURN resultado;
END$$
DELIMITER ;

SELECT *, verificar_salario_2000(remuneracao) FROM salario;

Stored procedure

08/09 e 14/09/2026

Blocos de comandos guardados no banco, com parâmetros de entrada e saída, laços e erros próprios.

  • Stored procedure é um bloco de comandos guardado no banco e executado com CALL. Diferente da function, não precisa devolver valor.
  • Parâmetros: IN (entra, padrão), OUT (sai, lido depois numa variável @x) e INOUT (entra e sai).
  • Laços: WHILE ... DO ... END WHILE e REPEAT ... UNTIL cond END REPEAT. Erros com SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '...'.
  • Exemplos dos slides: selecionar_1_disciplina, selecionar_prova_com_x_questoes, verificar_resposta, contagem_regressiva (WHILE) e contagem_regressiva_repeat.
DELIMITER $$
CREATE PROCEDURE contar_automoveis(OUT p_total INT)
BEGIN
  SELECT COUNT(*) INTO p_total FROM automovel;
END$$
DELIMITER ;

CALL contar_automoveis(@total);
SELECT @total;

A explicação completa (IN/OUT/INOUT, laços, SIGNAL e erros 1305, 1318 e 1064) está na seção Stored Procedure do guia principal.
